# JLZ agent entry point (read first, every session)

1. Read `docs/STATE.md`, `docs/ENGINEERING.md`, `docs/RESEARCH.md`, and the latest `docs/reports/` report before acting. These are the canonical handoff and decision records. Do not rely on previous chat memory.
2. Review `docs/research/attempted-ideas.md` before suggesting mathematical theories. Distinguish natural-file whole-archive evidence from synthetic controls and transforms plus external codecs.
3. **All lasting source, documentation, and workflow edits are made directly on `main`. No feature, research, or PR branches.** The sole normal exception is the ephemeral `jls-test/*` branch used to dispatch Test against `main`, automatically deleted by the trigger workflow. Local disposable experiment directories are allowed, but never create persistent research branches.
4. The accepted source is **Round 23**. See `docs/reports/2026-10-18-round23.md`: same-host ten paired full-Silesia medians 64,505,708 B → **63,658,799 B**, 6.712879 → **6.351571 s** encode and 2.515717 → **2.330026 s** decode. Historical Round 21 measured 63,770,766 B on a prior environment and remains separately documented; this exact figure was not reproduced from the uploaded corpus and Go 1.23.2. Do not mix historical figures and local paired data.
5. **YAGNI always.** Implement only demonstrably necessary scope. Prefer simple, measurable approaches and delete unused local experiments and rejected candidate code after documenting results. Comment non-obvious code, including invariants, bitstream layouts, compatibility decisions, and mathematical derivations; avoid tautological comments.
6. JLZ must remain one fixed automatic encoding procedure and exactly two CLI verbs, `compress` and `decompress`. No levels, optional user codec modes or ad-hoc flags. Internal automatically selected representations are allowed. Maintain `JLZ1` backward decode where practical; clearly report format incompatibilities before acceptance.
7. Never use DEFLATE, Zstd, XZ, Brotli, LZMA, or any existing compressor backend as JLZ's engine, fallback, terminal coder, or production path. Use other codecs **only** as external fixed benchmarks or clearly marked diagnostic transforms. No fake novelty claims; exact matching and standard entropy coding have prior art.
8. Acceptance: exact byte roundtrips, full archive bytes including metadata, unmodified baseline, *paired median of 10 whole-corpus encoding runs*, decoding performance, independent fixed Zstd/XZ reference columns. State per-file regressions, aggregate and worst cases. Rerun `go test -count=1 ./...`, `go vet ./...` and race checks appropriate to the change. Never call one run or selected windows a full-corpus benchmark.
9. User generally approves changes that improve aggregate size and encoding time, considering decoding, memory and important per-file regressions. **There is no fixed percentage acceptance threshold.** After a few consecutive diminishing improvements, investigate a meaningfully different structural idea rather than endless parameter tuning. Reject pointless complexity and disproportionate resource costs. Preserve reproducible prior versions.
10. Workflows: align with `jls` and `jls-*`: ephemeral `jls-test/*` branch triggers a fresh Test rolling prerelease then deletes trigger branch; nightly at 23:00 America/New_York only when package inputs changed; manual stable semantic release major/minor/patch/replace current. Test/nightly **completely replace** previous prerelease assets and tags. No executable/binary commits. Consult `docs/WORKFLOWS.md`.
11. After **every** substantive experiment, write a dated canonical report under `docs/reports/` containing hypothesis, change, corpus, full-file archived bytes, ten-run medians or screening-only labels, Zstd/XZ fixed references, validation, regressions, verdict. Update `docs/RESEARCH.md` and `docs/STATE.md` before finishing. Record negative experiments too. Do not orphan reports in experiment folders.
12. Priority after Round 23: validate BWT selection on diverse, legally reusable real-world corpora and resolve the mismatch between the reproduced local Round 21 archive total and its older historical 63,770,766 B figure using SHA-256 manifests and toolchain records. Round 23 improved aggregate performance but doubled `x-ray` per-file encode time, so avoid accepting disproportionate costs in new samples. BWT/MTF/zero-run/Huffman are established algorithms, NOT novel ones. The BWT suffix-index serialization coupling remains implementation-specific; preserve fail-closed checks, replace only with demonstrated need. Historical attempted-ideas inventory already exists in `docs/research/attempted-ideas.md`; document new real-world trials. For nonsensical continuation messages, proceed with the work without asking.
13. When giving results to the user: **what changed, one consistent comparison table, verdict, next target**. Be brief and explicit. For nonsensical continuation messages, continue the established workflow without asking.
