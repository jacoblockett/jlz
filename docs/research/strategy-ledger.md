## Research queue: structurally DISTINCT hypotheses, not parameter tuning

- **Match candidate-cost parsing (libdeflate minimum-cost path vs JLZ's one-byte lazy parser).** Most current parsing candidates are generated by shallow three-fingerprint buckets; a novel proposal must explain low enough marginal CPU and the actual token/entropy framing improvement. Cache candidates instead of rescanning or building a costly binary tree by default. Do not copy libdeflate code or adopt DEFLATE as a backend.
- **Different native match-finder indexing structures (liblzma HC vs BT), only with bounded-work proof.** Binary tree/high-quality candidates might recover ratio but risk encoder speed; contrast with the rejected simple dual-anchor exact-only replacement and expanded naive history; a genuinely different representation would complement transformed XOR/ADD math, not replace it.
- **Suffix-array construction/serialization overhead** in JLZ's own BWT transform: it presently constructs Go standard-library `index/suffixarray` and extracts ordering from `Index.Write` serialization. A **native, mathematically equivalent and faster suffix ordering extractor** could reduce encode time without changing compressed bytes or decoding; avoid unsafe reflection/unstable unexported internals. A new independently implemented SA builder must first beat actual BWT transform wall time on the real selected source blocks.
- **Complementary mathematical/scientific models** from `theory-backlog.md` that have not been meaningfully tested on the approved original-byte pipeline. Identify true novel scope beyond earlier generic XOR/grammar/semantic binding screens.
- **Externally studied compressors as inspirations, not dependencies:** Apple LZFSE (L/M/D sequences + FSE), LZ4/Snappy (cheap matching/direct copies and chunk boundaries), liblzma/LZMA (hash-chain vs binary-tree match finder), libdeflate (minimum-cost match parsing), Brotli (context/dictionary design), Zstd (strategy classes/sequence table reuse). JLZ already implements some broad paradigms; do not propose duplicates as new research.
