# Zstd superblock-trained shared entropy model versus JLZ independently modeled BWT segments

**Date:** 2026-10-20. **Disposition:** REJECT two concrete *intra-BWT block* native shared-table placements after complete selected-block component screening. No fully integrated codec, ten-run candidate, new mode, production source, third-party backend or PGO change.

## Origin, novelty and why this is not the older rejected table reuse

Studied actual Meta Zstd [`lib/compress/zstd_compress_superblock.c`](https://github.com/facebook/zstd/blob/dev/lib/compress/zstd_compress_superblock.c) Git blob `a1b4192cc3a6ea3e36ed6073f80b079b1d0e44f8`, including the mechanism of constructing entropy tables once from an entire superblock's sequence/literal statistics and then emitting individually framed subblocks using *repeat-table* mode. This is distinct from simply carrying a trained FSE table across independent prior compressed blocks. Zstd shares table-description cost while amortizing model construction and retains separately decodable subblock bodies within a larger frame.

JLZ has already (1) tested FSE normalized-model reuse from **one independent cross-block group to the next**, an optimistic only ~5.3KB benefit with dependencies; (2) accepted mode16 **two/four independently trained BWT MTF symbol subparts** when locally profitable; and (3) rejected excessive other BWT entropy partition counts/change-point sweeps. **This trial tests a new supplementary arrangement:** within a *currently selected segmented 256KiB original-source BWT block*, use **one jointly trained normalized rANS table shared among all independently byte-renormalized subpart bodies**, or one per adjacent pair when there are four subparts. It avoids repeating header/model normalization for each subpart, but cannot be assumed to preserve the local distributions that originally made splitting profitable.

**Causality:** Local entropy models are only selected when their independent distributions overcome separate table-header cost. Once that condition holds, replacing them with one global distribution increases code length more than it saves in headers, in this measured native data. No per-block winners mean there is no native frame-size selector worth integrating, regardless of whether training one shared table would reduce encoder setup time. Shared-model decoder would introduce new subtype and new table-lifetime handling for an archive that already increases everywhere.

## Scope-limited decision and further variants

**REJECT only this concrete BWT-selected intra-superblock table-sharing scheme**: both shared-all and pair-adjacent variants lose on every eligible currently selected segmented block. No practical beneficial supplementary placement in this exact location, so no 10-run full original-corpus candidate, Windows/race test or new-format compatibility test was warranted. The alternative does not change any production code or existing decoder.

**Do not close Zstd's general superblock mechanism**. Zstd gains are associated with a specific LZ parse and sequence/literal symbol distributions. JLZ's separate **mathematical opcode, literal-length, distance and literal** streams have not had this *shared model across subblocks of a single fully parsed sequence store* placement benchmarked with actual matched-token fidelity. A successor must first attribute sequence-symbol costs and avoid repeating the rejected cross-group previous-table-reuse oracle and independently coded FSE variants. Also, alternative shared predictive tables with low overhead must be materially distinct, not adjacent partition-count sweeps.
