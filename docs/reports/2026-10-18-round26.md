# Round 26: Four-lane first-difference representation (rejected)

**Date:** 2026-10-18. **Approved compressor remains Round 25 on `main`.** All experiment source code was confined to disposable local copies. Only this report, raw measurements and updated canonical indexes were committed.

## Hypothesis and historical relationship

Round 25 uses automatically selected reversible byte-lane separation before independently packing each lane with native Huffman/RLE/raw coding. A natural next structural hypothesis is that sequential values **within one residue-class lane** carry additional difference predictability. This is related to historically attempted fixed-lag XOR/subtraction transforms and interleaved mathematical streams in `docs/research/attempted-ideas.md`, but **those prototypes did not establish this exact lane-separated, standalone native JLZ representation**, and some older apparent gains used downstream external codecs.

Tested a fixed four-byte residue stride. For each of four lanes, encode the smaller **fully serialized** native representation among (a) original bytes, (b) XOR against the immediately preceding byte in that lane, or (c) subtraction modulo 256 against that preceding byte. The first symbol remains literal, and reversal is exact. The experimental proposed extension used high-bit stride metadata under existing internal lane block mode 13, with a per-lane predictor symbol 0/1/2 and standard independently framed native streams. The Round 25 decoder would reject the new high-bit form as intended, while the experimental decoder supported old and new forms.

The experiment adds no external compressors and no CLI settings. Sampled predicted-lane sizes were compared against the actual incumbent whole-file JLZ1 archive, including metadata and digest. Candidate archives were chosen only on a strict actual complete-archive size win.

## Initial isolated native-lane block screen

All 20 full source files from the accepted Silesia (12-file, **211,938,580 B**) and prior heterogeneous convenience corpus (eight files, **70,159,124 B**) were inspected with the existing stride-four native lane packer and the candidate per-lane XOR/sub predictor, including their coded stream framing. These are **component-only** totals, not standalone archive comparisons:

| File | Plain stride-4 packed-region total | Predicted stride-4 candidate | Difference |
|---|---:|---:|---:|
| Silesia `x-ray` | 5,887,457 B | 4,602,117 B | -21.83% |
| Silesia `mr` | 4,296,597 B | 3,979,732 B | -7.37% |
| External TTC font | 17,240,508 B | 16,294,886 B | -5.48% |
| External SoundFont | 5,535,597 B | 5,390,274 B | -2.63% |

Most other files showed negligible changes, and `mr`/font still lost to other automatically chosen JLZ representations. These local component figures motivated a full-file screen, **not** an acceptance decision.

## Ten paired complete-archive benchmarks: unfiltered candidate

Built separate, untouched Round 25 and experimental candidate Go 1.23.2 linux/amd64 test executables. On each corpus, ten pairs alternated source execution order, loaded input bytes outside the clocks, encoded each complete original file to native JLZ1 archive, and decoded and compared reconstructed bytes. **All 12/12 Silesia and 8/8 heterogeneous source files restored exactly in every run**. Whole-corpus medians are calculated from each run's summed encode/decode duration. Raw nanosecond measurements are preserved in [Silesia paired10](2026-10-18-round26-silesia-paired10.csv) and [heterogeneous paired10](2026-10-18-round26-external-paired10.csv).

| Metric | Unchanged Round 25 | Unfiltered candidate | Difference |
|---|---:|---:|---:|
| Silesia archive size | 63,104,117 B | **62,980,065 B** | **-124,052 B (0.20% smaller)** |
| Silesia encoding median | **7.506952 s** | 7.826821 s | **4.26% slower** |
| Silesia decoding median | 2.804750 s | **2.761770 s** | **1.53% faster** |
| External archive size | 32,085,884 B | **31,940,577 B** | **-145,307 B (0.45% smaller)** |
| External encoding median | 3.099226 s | **3.096116 s** | **0.10% faster** |
| External decoding median | **0.755200 s** | 0.760106 s | **0.65% slower** |

Only Silesia `x-ray` and external SoundFont changed archive bytes; other Silesia and heterogeneous archives remained byte-identical to the Round 25 encoder output. Ten-run per-file encoding medians: `x-ray` **0.302010 → 0.382910 s** (26.8% slower); SoundFont **0.108368 → 0.161485 s** (49.0% slower). The extra work on the other, unchanged files also inflated Silesia's whole-corpus encode time.

The initial candidate passed `go test -count=1 ./...`, `go vet ./...`, and targeted `go test -race -count=1 -run 'TestPredLane|TestLane|TestCross' ./...`. Unit tests exercised varied, unaligned/random lane lengths, invalid predictor flags, truncated streams, full-archive byte equality, and corruption rejection. This is **not** a full 27-file cross-version compatibility audit, which is not necessary to reject the experiment.

## Cheaper selection gate screen: also rejected

A second isolated copy added a fast **optimistic Shannon lower bound**: for each sampled original block, accumulate per-lane histograms of original, lag-four XOR and lag-four subtract bytes in one source pass. Reject expensive serialized Huffman sample encoding unless the optimistic best predictor distribution is plausibly smaller than the incumbent archive's sampled rate. This requires no false assertion that Shannon estimates equal actual coded bytes; subsequent winning decisions still use exact archived sizes.

The optimization preserved both candidate corpus sizes and passed regular unit tests and vet. **Six alternating Silesia pairs**, not ten, were completed as a screening check before stopping further resource expenditure on a consistently negative result:

| Metric | Round 25 baseline | Cheaper-gate candidate |
|---|---:|---:|
| Full archive bytes | 63,104,117 | 62,980,065 |
| Encoding median of six pairs | **7.4445 s** | 7.6050 s (**2.16% slower**) |
| Decoding median of six pairs | 2.8065 s | 2.7969 s (0.34% faster) |

See [six-pair gate screening log](2026-10-18-round26-fastgate-silesia-screen6.csv). **These are six-run screening medians and must not be represented as ten-pair promotional results.** The conservative selection prefilter reduced, but did not eliminate, the CPU cost of the predicted-lane representation. The independently measured external ten-pair comparison above is for the **unfiltered**, not the cheaper-gate implementation; only a one-run external size/roundtrip check was performed with the gate.

## Fixed external reference context

Historical Zstd-3 **66,216,569 B** and XZ-6 **49,233,340 B** sizes concern the complete Silesia corpus only. These figures were not rebenchmarked. Their previous-host CLI times do not compare with this experiment's in-memory paired timings. The older historical Round 21 reproducibility discrepancy remains unresolved.

## Decision and next priority

**REJECT both variants. Do not change the Round 25 encoder or decoder.** The general predictor is reversible and genuinely native, and it finds a small positive byte opportunity on `x-ray` and SoundFont. However, the first complete Silesia benchmark slows encoding 4.26% for 0.20% size gain. The optimized selection gate still slows encoding 2.16% in six-pair screening. The retained speed/complexity tradeoff fails YAGNI. No new codec bits or compatibility constraints have been promoted.

**Next:** stop successive tweaks to the byte-lane family. Pursue larger structural opportunities in *math-match literal and distance metadata*, using the Round 18–20 selected-stream diagnostics as **hypotheses only**, never standalone gains. Use original, legally reusable full files and complete archive medians; pay particular attention to additional CPU cost and real output bytes. Preserve prior attempted-ideas inventory, current Round 25 baseline and existing GitHub build cache.
