# Round 18: Selected-stream cost audit and contextual opcode prototype (rejected)

**Date:** 2026-10-18. **Approved base:** Round 16, 66,519,205 B on Silesia. **Verdict:** REJECT all prototypes; no approved source or archive-format change. Experiments ran in disposable local copies and are not committed as dead production code. All permanent repository edits are directly on `main`.

## Hypothesis and first diagnostic

The Round 17 raw-input entropy estimator failed because input byte frequencies are not the same as the cost of *tokens that actually win the final archive*. This round measured real match token streams and then independently parsed the accepted final Round 16 Silesia archives to avoid crediting losing representation candidates.

**Diagnostic all parsed 256 KiB blocks** (not all selected in final archive):
- Paired-nibble opcodes with current sparse Huffman: **2,467,569 B**.
- The same opcodes represented as individual bytes and encoded using the existing adaptive order-1 arithmetic coder: **2,043,854 B** (423,715 B smaller on these intermediate streams).
- These are standalone diagnostic stream sizes, **not** archive gains. The arithmetic alternative also entails nontrivial CPU cost.

## Selected final-archive composition

The accepted Round 16 Silesia archives use grouped mathematical/match blocks on ten files. `sao` selects the whole-file parallel-native codec and `x-ray` the predictive codec. Across the **750 selected match blocks** in the ten grouped archives, the packed stream contribution was:

| Selected match stream | Stored bytes |
|---|---:|
| Literal payload | 28,189,554 |
| Distance metadata | 15,078,127 |
| Combined literal/copy length bytes | 7,105,789 |
| Additional copy-length stream | 1,499,572 |
| Opcode stream | 2,436,831 |
| Transform masks | 5,495 |

Counts are for selected match-block stream envelopes and do not sum to the complete archives: other block types, file-level framing/checksums, and entire non-match files are deliberately excluded. Of selected distance blocks, **669 use the existing logarithmic-slot codec**, 76 Huffman, and five raw; **732 selected literal streams use the arithmetic codec**.

**Research implication:** Improving a stream's size on hypothetical parsed blocks does not demonstrate a comparable final-archive gain; the selected distance/literal streams dominate real file bytes.

## Prototype A: Previous-operation-conditioned static Huffman opcode stream

Used two Huffman contexts (previous symbol was a literal vs another reference), with a fixed table and exact reconstruction of the existing paired opcode nibbles. The old packed codec competed automatically on complete stream size. Local test source modified the packed opcode producers (including cross-region history blocks) and added a reversible stream codec identifier. No new search pass, user option, or external compressor.

The prototype initially failed on `mozilla`: source opcodes are numbered **1 through 9** (the leading mode constant consumes iota zero), while the first prototype mistakenly allocated only symbols 0 through 8. A full-file byte-exact roundtrip caught the error. Extending the alphabet to include symbol 9 fixed it; unit tests, uncached `go test -count=1 ./...`, `go vet ./...` and complete Silesia roundtrips passed afterward. This is why synthetic-only token tests are inadequate.

**One complete 12-file Silesia screening pass**, not a ten-run paired benchmark:

| Metric | Approved Round 16 | Prototype |
|---|---:|---:|
| Complete archive bytes | 66,519,205 | 66,470,433 |
| Absolute size change | — | **-48,772 B (0.0733%)** |
| Encoder timing | Previous controlled benchmark 13.290 s median | 16.806 s **single, unpaired screening run** |

The times are **not comparable**; no candidate timing median was established. Size changes by file: `mozilla` -31,657 B, `nci` -14,081 B, `samba` -2,444 B, `ooffice` -589 B, `xml` -1 B; other seven files unchanged. No size regressions. The size gain alone is far below the 3% skepticism threshold, while the new codec would also make new-format archives unreadable by the approved decoder and add codebook handling. **Reject, no ten-run promotion benchmark.**

## Diagnostic B: Residual distance low-bit entropy

Inspected actual selected distance streams using slot coding: **7,751,671 distance values**, **83,636,732 raw extra bits**. An optimistic independent probability model conditioned only on low-bit position would save **52,828 B** before any modeling/framing cost; conditioning on both slot width and bit position would save **65,008 B**. These are idealized Shannon-information bounds for the measured *fixed contexts*, not implemented or demonstrated savings. They do not support adding a slower per-bit entropy coder to ~10.45 MB of largely unpredictable low bits.

## Diagnostic C: Group-wide literal arithmetic state / alternate length slots

Tested whether reusing one arithmetic state over several neighboring selected block-literal streams could avoid local model warm-up. Partial results on eight Silesia files showed only modest isolated savings; the diagnostic reached its execution budget before a complete corpus result. **Incomplete analysis, no codec candidate, no end-to-end win.** Also probed varint-slot recoding of the selected length streams: the first eight files showed only single-digit KB savings in most cases. Neither result supports a new archive format or an additional expensive pass.

## References, validation scope and decision

Corpus: complete 12-file Silesia, **211,938,580 input bytes**. Approved baseline remains Round 16: **66,519,205 B**, paired ten-run medians **13.290 s encode / 5.311 s decode** from Round 16 (different measurement conditions from prototype screen).

External fixed references (complete archive bytes): **Zstd-3 66,216,569 B, 1.256 s** historical CLI; **XZ-6 49,233,340 B, 116.989 s** historical CLI. Those times are not directly comparable with JLZ in-memory timings.

No ten-run paired benchmark, decoding-speed median, comprehensive race suite, or CI Test release was run for this rejected codec. The code was not promoted.

**Next priority:** Seek a genuinely different *high-leverage* native representation or predictive model for **selected literal bytes and match distances**, with a cheap theoretical screen against actual final-archive streams. Do not revisit opcode Huffman partitioning, width-conditioned raw low-bit arithmetic, or block-shared literal arithmetic solely for marginal warm-up savings.
