# Round 17: Sampled literal-cost scoring and probability table (rejected)

**Date:** 2026-10-18. **Baseline:** approved Round 16, `66,519,205` bytes on full Silesia. **Verdict:** no promotion; source remains unchanged. All research was done in local disposable copies, with documentation committed to `main`.

## Experiment A: Entropy-calibrated match scoring

**Hypothesis:** Estimate each region's literal symbol cost using one bounded distributed 16,384-position sample; use that estimate in the existing one-pass match scorer rather than a uniform five-bit literal / six-bit local-copy score. No new matcher pass or archive format.

**Implementation screened:** when sampled byte entropy was below 4 bits, use a 4-bit literal score; above 7.25, use 6 bits; otherwise retain 5. Local copies score one extra bit. The unchanged parser, token grammar, and decoder were used.

**First complete 12-file Silesia screening pass (NOT a ten-run benchmark):**

| Measurement | Round 16 | Candidate |
|---|---:|---:|
| Total complete archive bytes | 66,519,205 | 66,472,539 |
| One observed encode run | 17.294 s | 19.564 s |
| Byte-exact full-corpus restoration | Yes | Yes |

Archives were 46,666 bytes (0.070%) smaller, but the candidate's observed encode run was substantially slower. Single-run times are **not** a reliable speed benchmark and are **not** claimed as ten-run medians. The full 10-run promotion benchmark was intentionally not conducted after the unfavorable screen.

Per-file size changes: `nci` -41,090 B, `mozilla` -3,695 B, `samba` -1,946 B, and `mr` **+65 B**; all other files unchanged in size. One complete pass and uncached `go test -count=1 ./...` passed. No full race suite, cross-platform release, or ten-run benchmark was claimed.

**Conclusion:** Zero-order entropy of the original bytes is a poor proxy for the cost of the *residual literal stream after matching*. It can shift token choices enough to increase search/coding work for negligible whole-archive savings. Do not retry a global byte-histogram scorer without better evidence of actual token-stream costs.

## Experiment B: Small-count arithmetic probability lookup

**Hypothesis:** Most order-one arithmetic-model count pairs are small. Use a read-only triangular lookup table to replace divisions when the count sum is <= 512; keep the old exact division otherwise. This preserves the arithmetic bitstream and all decoder modes.

**First complete Silesia screen (NOT a ten-run benchmark):**

| Measurement | Round 16 | Candidate |
|---|---:|---:|
| Total complete archive bytes | 66,519,205 | 66,519,205 |
| One observed encode run | 12.320 s | 12.436 s |
| Byte-exact full-corpus restoration | Yes | Yes |

The 132K-entry `uint16` lookup consumes about 264 KiB of static memory, and produced no convincing speed improvement. The apparently precise single-run timing difference should not be extrapolated. `go test -count=1 ./...` and `go vet ./...` passed locally. No ten-run benchmark or full race suite was run because the candidate failed screening.

**Conclusion:** Additional random table lookups are not obviously cheaper than CPU division in this hot path, especially when large-count contexts still fall back to division. Reject the added permanent memory and complexity.

## Reference and disposition

Corpus: original twelve Silesia files, **211,938,580 bytes**. Historical external full-archive references: Zstd-3 **66,216,569 bytes** (1.256 s historical CLI); XZ-6 **49,233,340 bytes** (116.989 s historical CLI). External times are not directly comparable with local JLZ in-memory screenings.

No candidate reached promotion. **Approved JLZ remains Round 16**, 66,519,205 bytes, with previously verified ten-run paired encoding/decompression medians **13.290 s / 5.311 s** from the Round 16 report. No new `JLZ1` block mode, production source, binary or release was committed.

## Next research target

Use *already parsed or encoded* token-stream statistics rather than raw-source zero-order entropy to estimate actual match and literal costs. Prefer a zero-additional-pass diagnostic that can demonstrate sizeable theoretical whole-file savings **before** implementing a new format or entropy coder. Preserve the accepted separate literal-run/copy-length models and YAGNI.
