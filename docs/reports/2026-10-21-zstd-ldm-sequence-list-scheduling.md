# Zstd independent-group LDM sequence list: historical long-window collision and bounded schedule

**Date:** 2026-10-21. **Status:** native-Go full-corpus experimental implementations, exact source restoration; **REJECT raw long-window hybrid, DEFER distinct precomputed group-hint schedule** because no reliable speed improvement. Production source, PGO and accepted references unchanged.

## Zstd mechanism, novelty, and implementation

Primary Meta mechanisms: [`zstd_ldm.c`](https://github.com/facebook/zstd/blob/dev/lib/compress/zstd_ldm.c) generates source-side raw long-distance sequences and [`zstdmt_compress.c`](https://github.com/facebook/zstd/blob/dev/lib/compress/zstdmt_compress.c) feeds sequence work to independent compression jobs. The previous [JLZ group-local sparse LDM experiment](2026-10-21-zstd-group-local-sparse-ldm.md) had built a gate map for each candidate block and another map during mathematical reference finding. Here, prototype S1 instead **precomputes a group-local source-verified 64-byte exact anchor list once** per independent four-block group, with source-byte lookups every 16 bytes beyond the existing 128KiB near reference window, and sends only immutable candidate offsets to the original parallel block parsers. Supplemental exact anchors compete with unchanged local exact/XOR/ADD and lazy match decisions, and continue through existing native command/distance/length/literal entropy packing. No Zstd backend or external codec.

A source-identity and historical novelty review after the first prototype exposed an important **accidental confound**: the first version failed to restrict `matchIndex.indexed` to the last 128KiB when an earlier group prefix was supplied. That change widened the **ordinary per-byte exact/XOR/ADD near index** across the entire available group (as far as 768KiB), in addition to passing sparse hints, partially repeating historical [R63 broad 512KiB matcher](2026-10-19-round62-63-math-sequences-far-history.md). This invalidates any claim that its larger compression savings were from *only* new Zstd sequence precomputation. Corrected S2 restores the ordinary near-index lower bound `max(0,start-128KiB)` and retains only truly sparse far hints. A second S2 variant reuses the hash map with `clear()` across all groups rather than reallocating it.

## Validation, format, and scope decision

For corrected S2, `go test -count=1 ./...` **PASS**, `go vet ./...` **PASS**, targeted engine `go test -race -count=1` for existing archives, cross-history, exact/XOR/ADD, corrupted input and concurrency **PASS**, and `CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build ./...` **PASS** (compilation, not Windows runtime). The corpus source manifest **12/12 PASS**. Archives using >128KiB far distances require the S2 group-aware decoder; new decoder continues decoding existing 128KiB-history archives. Old accepted decoders are **not** claimed to decode newly written distant-reference archives. Four-block groups remain independently reconstructible. The current production codec was never changed.

**Decision:** The truly new source-index amortization placement reproduces G1's **+0.040733 pp** compression gain and its CPU overhead remains unproven; **DEFER/NO CODE PROMOTION**. The S1 extra +0.084901 pp came from broadening the normal matcher index, a near-duplicate of rejected historical longer windows; **REJECT S1**. Do not relabel wider near-window indexing as LDM novelty. Full LDM family is **OPEN for truly distinct parser-independent scheduled sequence injection** that substitutes rather than adds work, or a proven bounded selection/traversal architecture. Do not repeat 16B stride tuning, simple map-reuse timing, near index window sweeps, or raw far-source coverage estimates.
