# Indirect context-state probability maps and ISSE correction on JLZ native entropy streams

**Date:** 2026-10-20. **Decision:** REJECT the concrete adaptive indirect context coder integrations, retain accepted codec/PGO/format unchanged. Significant **full original Silesia** size reductions were verified on candidate-only single passes, but encode and decode work was much too expensive to justify a new wire subtype. No integrated ten-run timing or promotable candidate.

## Novelty gate and actual reference source

Before prototyping, checked `docs/research/strategy-ledger.md`, `docs/research/layer-placement-matrix.md`, `docs/research/attempted-ideas.md`, and historical adaptive entropy / PPM / bytewise-context reports. The nearest previous JLZ experiments were (a) two-level **direct** order-1 prefix/previous-byte frequency estimates in `entropy/arithmetic.go`, (b) direct per-context exponentially moving binary probabilities, which saved bytes on mathematical literals but hurt complete-corpus speed, (c) three static context-rANS models and low-accuracy bytewise Fenwick coders, and (d) bounded order-2 PPM escape/backoff with exclusion, which expanded both source/BWT and mathematical literal streams. This trial instead indexes a **shared adaptive state-map** via each context's **8-bit quantized zero/one-history state**, allowing different contexts with equivalent histories to learn the same probability estimate. That is a distinct statistical generalization mechanism, not a retry of the two moving averages, PPM context count cap, or static symbol tables.

Directly inspected real ZPAQ [`libzpaq.cpp` ICM/ISSE source](https://github.com/zpaq/zpaq/blob/master/libzpaq.cpp) including the ICM state-map prediction and update paths and ISSE learned predictor adjustments. Implemented original simplified native-Go experiments, **not** ZPAQ's actual state machine, hashed 16-way row architecture, logistic weights or JIT implementation. ZPAQ was a research reference only, never a backend. The simplified ICM maintains 65,536 previous-byte/binary-prefix 8-bit history states plus 256 global-prefix states, and eight shared 256-state probability maps. Each bit updates its contextual quantized history and state-map prediction; one local/global blend generates a binary probability without side tables in the archive. A second variant added a learned per-state affine gain/bias adjustment, testing the distinct ISSE idea. Both use synchronized original encoder/decoder state and preserve exact byte identities.

## One-pass, fully integrated current-JLZ supplements

In **disposable local working copies** of verified accepted production Go source, introduced conditional packed entropy codec6 readable by candidate decoder; older accepted compressed streams modes0–5 remain readable. Changed **only BWT encoding** to conditionally supplement existing `packFiniteState` with the new indirect model (all native streams and full archive framing charged), preserving mathematical match, BCJ and field-aligned lanes. The range-output candidate used the same indirect probability model but replaced E3 bit renormalization with a **native byte-renormalized 32-bit range coder** inspired by already documented LZMA output architecture; distinct placement and shared model, not an additional third-party codec. The direct-only attempt removed the duplicate old entropy pass, taking the new model for all eligible BWT streams; it retained raw fallback but could enlarge some per-file representations.

Each executed complete original-Silesia screen encoded **all twelve full source members**, produced one archive per file, decoded every one, compared exact original bytes and SHA-256. **These are SINGLE SCREEN RESULTS, never ten-run medians**, and comparisons to accepted historical measurements are unpaired and host-sensitive. Candidate-only tests ran with committed root `default.pgo` unchanged.

The H2 separately timed pass was **12/12 original members reconstructed exactly**, and two retained **historical accepted** complete archives (`mozilla`, `sao`) decoded exactly with the new candidate decoder (2/2). Size improvements were entirely in dickens **-62,279**, mr **-144,322**, ooffice **-37,505**, osdb **-257,531**, reymont **-55,952**, webster **-226,095**, xml **-9,517**, x-ray **-92,831** B, while mozilla/nci/samba/sao were unchanged. **No per-file size regressions in H2.** H3 **regressed nci by 179,169 B relative to accepted** while giving back 195,550 B of overall compression gain compared with H2, and barely improved encoding speed. The proposed direct-only work reduction did not eliminate the per-bit adaptive computation, so even its single-run encode was **~74% slower** than the historical accepted ten-run median; H2 decode was **~99% slower** than historical accepted median, with limited caveats about unpaired system timings. These are too large to attribute to small codec sampling effects or promote as practical improvement without a fundamentally different algorithm.

**Reference codecs NOT rerun:** Zstd-3 original Silesia 66,216,569 B / 1.2561 s encode / 0.8551 s decode; XZ-6 49,233,340 B / 116.9892 s encode / 2.3079 s decode. Reference CLI timings and JLZ in-memory timings differ.

## Validation, tradeoffs and final decision

Native-Go component model and symmetric decoder exact in both placements; full-source BWT inverses, encoder checks, all 12 real integrated per-file restorations and two historical archive restorations PASS. Rejected H2 local candidate `go test -count=1 ./...`, `go vet ./...`, targeted race test on new BWT coder, and Windows/amd64 CGO-disabled cross-build PASS. No native Windows runtime, comprehensive fuzzing or corrupt/truncated new subtype fuzz matrix was performed; the outer archive checksum validates source identity and decoder bounds for existing formats. All source files and experimental binaries remain disposable, **none committed**. PGO SHA-256 `3b35cda74832360a252b63c1805e025aa1f4ed7a4fe4124d9a55929a6e86289f` unchanged.

**Reject these concrete JLZ ICM/ISSE and ICM/range placements due to large real encoding and decoding work, despite confirmed ratio savings.** This is an actual architectural gain in BWT modeling but not a viable practical codec change; do not retune state buckets, shared-map probabilities, affine gains or legacy entropy gating. The broader question of deriving similarly conditional compression savings using **table-driven, low-serial-work decoding** remains untested, but ordinary static context rANS, four-state FSE, one-step ISSE and prior per-context EMA are already recorded negatives. Require clear new algorithm and selected-domain cost feasibility before another code experiment. No production code/wire changes, current remains **58,767,739 B / 4.7873709325 s / 1.8721679705 s**.
