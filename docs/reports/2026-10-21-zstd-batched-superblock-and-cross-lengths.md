## Novelty / upstream implementation audit

Primary source: [Meta Zstd sequence superblocks](https://github.com/facebook/zstd/blob/dev/lib/compress/zstd_compress_superblock.c), especially `ZSTD_compressSubBlock_sequences` and sequence-length-based subblock partitioning; [Zstd sequence-store code](https://github.com/facebook/zstd/blob/dev/lib/compress/zstd_compress_sequences.c). JLZ already separately codes opcodes, length varints, distance varints, transform bytes and literal bytes. Crucial historical collision: **JLZ Round 16 already promoted separate literal and copy-length entropy streams in its *ordinary* mathematical packed modes 10/11**. The accepted *cross-history block type 9*, which accounts for most selected math blocks, still encodes **one merged length stream** via `packCrossRegionTokens`. This **cross-history placement**, without any second match parse, is the genuine new experiment, not novelty of the original length split itself. Historical R58 length-*conditioned* distance splitting lost, R50 opcode-conditioned state models were source screens, and [2026-10-20 selected-stream role-distance split](2026-10-20-selected-stream-layer-screens.md) showed only 12,524 B on previous original block screens. Same coding family, independently costed new selected-stage placement, not falsely described as a wholly new algorithm.

## Fully integrated native-Go two-way cross-length codec

In a disposable original-Go source copy, added **`blockCrossSplitLengths = 20`** to the independently decodable `modeMixedCross` block grammar. The existing parser produces tokens once. Candidate `packCrossRegionTokensPreferred` invokes `splitMatchTokens` once, native-packs the opcode, distances, transforms and literal stream **once**, then compares the actual framed `packFiniteState(mergedLengths)` with the two independently packed `packFiniteState(literalLengths)+packFiniteState(referenceLengths)` bodies. It selects new block type 20 only when strictly shorter, otherwise byte-identical old cross type9. The decoder accepts both mode9 and mode20; mode20 is reconstructed using the *already existing* `decodePackedWithLengthMode(...,split=true)` with the unchanged bounded 128KiB cross-history. Input size, groups, match tokens, metadata, current worker scheduling and root PGO unchanged. **No codec-backend imports.**

**Full original 12-file archive result**, including all framing/metadata: **58,767,739 B (72.271334931% reduction) → 58,481,941 B (72.406184377% reduction), +0.134849446 percentage points (better), -0.486317842% in compressed bytes (better)**. Every one of the 12 original complete files restored exactly and 12 source manifest SHA-256s matched. Compressed size improvements: mozilla **-219,417 B**, samba **-63,735 B**, ooffice **-2,646 B**; **other nine file sizes unchanged**. A second full candidate pass confirmed the exact 58,481,941 B total. This is a **one-pass complete-corpus archive-size result**, **not a qualified ten-run median**.
