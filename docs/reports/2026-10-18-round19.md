# Round 19: Literal predictor, distance-slot, and exact-reciprocal screens (rejected)

**Date:** 2026-10-18. **Approved baseline:** Round 16, 66,519,205 B on the full 12-file Silesia corpus. **Decision:** REJECT all candidates; keep the approved codec untouched. Local disposable experiment copies only; this report and handoff updates are the sole changes to `main`.

## Purpose and evidence

Round 18 showed that actual selected match blocks account for ~28.19 MB of compressed literal stream payload and ~15.08 MB of distance metadata. These experiments test cheap *predictability* before adding any novel entropy stream or decoder mode. They inspect the **existing selected Round 16 archives**, not losing intermediate parses, across the ten grouped/match-bearing files. The two remaining Silesia files use other top-level codecs and are included in the full-corpus encoder screen.

Input: twelve Silesia files, **211,938,580 B**. Historical complete-archive references: **Zstd-3 66,216,569 B / 1.256 s** and **XZ-6 49,233,340 B / 116.989 s** (historical CLI compression timings; not directly comparable with JLZ in-memory measurements).

## A. Reconstructed-output literal predictors (diagnostic only)

Recovered original literal-run bytes from selected match blocks and computed reversible XOR-previous-output, subtraction-previous-output, and second-difference residuals. Counted first-order literal-byte conditional entropy across the **750 selected match blocks**, with context reset for each block. This is an *idealized distribution estimate*, not a compressed-archive size or implemented wire codec.

| Raw literal representation | Unpacked bytes | Idealized first-order conditional size |
|---|---:|---:|
| Current selected literal stream bytes | 39,562,459 | 30,837,025 B |
| Original literal bytes (before selected residual transform) | 39,562,459 | 30,835,661 B |
| XOR preceding reconstructed output byte | 39,562,459 | 34,395,168 B |
| Subtract preceding reconstructed output byte | 39,562,459 | 34,731,011 B |
| Second-order finite difference (byte modular arithmetic) | 39,562,459 | 37,632,485 B |

The output-neighbor transforms are worse by multiple megabytes even in this favorable idealization. The current actual compressed literal streams use an arithmetic bit-prefix model and occupy about **28.19 MB**, so do *not* compare these idealized byte-level estimates directly with actual stream sizes as interchangeable codecs. **Rejected before implementation**.

## B. Order-two adaptive literal-byte context (diagnostic only)

Evaluated a lightweight **online/prequential** order-two byte model against an identically smoothed order-one model over the actually selected literal byte streams (contexts reset at each block, 39,562,347 bytes in qualifying streams). Both estimates use per-byte probability mixtures with one pseudo-count and evidence-weighted backoff; the second-order model adds an approximately 32 MiB dense conditional-count table per instance.

| Online estimate | Estimated size |
|---|---:|
| First-order/backoff model | 29,212,286 B |
| Additional two-byte context with backoff | 29,823,631 B |
| Difference | **+611,345 B (worse)** |

The estimate is not JLZ's actual bitwise arithmetic coding model; it measures whether the *additional* second-order context is already economically promising. The answer was negative, especially for Dickens and Webster; it helped MR only modestly. **Reject any new second-order codec mode** based on this screen.

## C. Distance-width predictive coding (diagnostic only)

For the **7,751,671 distance values** in selected logarithmic-slot streams, compared the byte-compressed existing width sequence against a reversible signed difference from the preceding width, using the same native Huffman/raw stream selector for both. The low distance bits are not changed.

| Width stream | Packed bytes |
|---|---:|
| Existing absolute slot widths | 3,540,311 |
| Signed difference from previous width | 4,101,214 |
| Regression | **+560,903 B** |

Entropy from aggregate width histograms was 28,850,377 bits unconditional versus 28,638,111 bits conditioned on prior width, just **26,533 B** of optimistic improvement before any model/framing cost. Conditioning on explicit operation type alone explains only about **49 B** (7,751,665 explicit-copy distances, nearly all one opcode). Not a worthwhile format addition.

## D. Exact fixed-point reciprocal instead of arithmetic probability division (working prototype, rejected)

The hot `bitModel.probability` routine divides two scaled counts by their total. Implemented a compact **2049-entry uint32 reciprocal table** with one exact integer correction per probability. **Exhaustively checked** every numerator `0..total` for `total=2..2048` against the existing division. The returned probability and therefore the archive format and bitstream are unchanged; `addCount` maintains the stated denominator bound.

The candidate passed uncached `go test -count=1 ./...`, `go vet ./...`, and the twelve complete Silesia files each produced **byte-identical** archives. A controlled-order, one-run-per-variant *screening pair* measured:

| Metric | Approved Round 16 | Reciprocal candidate |
|---|---:|---:|
| Complete Silesia archive bytes | 66,519,205 | 66,519,205 |
| Encode seconds, single unpaired-order screen | **13.716** | 14.914 |
| Measured improvement | Baseline | **None** |

The timings are **single screens, not 10-run medians**. An earlier candidate screen was interrupted near its end; that interruption was *not* treated as a successful benchmark. The completed pair offers no evidence of an encoding speed gain and adds an extra lookup and correction path; rejected without the expensive ten-pair promotion process. No targeted race suite, decoder timing median, or GitHub Test release was necessary for unpromoted experiments.

## Implications and next work

Simple reconstructed-output first/second differences and extra second-order literal context did not expose valuable residual structure. Distance-width sequences have weak first-order correlation, and opcode labels add no explanatory power. Replacing variable division with exact precomputed reciprocals is not reliably faster.

**Approved Round 16 remains at 66,519,205 B**, with its previously documented ten-pair median of **13.290 s encode / 5.311 s decode**, measured under Round 16 benchmark conditions; do not compare that historical median to this round's single screens as a paired result.

For the next experiments, stop exhaustively partitioning the existing metadata and target a truly different cost-effective *selected-data representation* with substantial end-to-end promise. Prefer cheap negative screens first, document YAGNI scope, explain any non-obvious bitstream invariants, and keep all repository source changes directly on `main`.
