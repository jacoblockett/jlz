# Zstd group-local sparse long-distance anchors: full-codec native Go screen

**Date:** 2026-10-21. **Result:** concrete sparse same-group integration saved **86,330 B** on original full Silesia, but no repeatable speed improvement. **SCREENED / NO PROMOTION.** All code and tests were in disposable local working copies; production `main`, root PGO and archive subtype definitions unchanged.

## Theoretical hypothesis and checked novelty

Source inspiration: [Meta Zstd long-distance match finder](https://github.com/facebook/zstd/blob/dev/lib/compress/zstd_ldm.c) plus [Zstd parallel worker LDM scheduling](https://github.com/facebook/zstd/blob/dev/lib/compress/zstdmt_compress.c). Existing JLZ has two-slot exact/XOR/ADD hash history, short lazy parse, independently decodable groups of four 256KiB blocks, with 128KiB decoded prefix supplied to each block. Prior **R63** enlarged the **ordinary per-byte matcher** lookback to 512KiB (+267,104 compressed B saved on an older baseline, but slow in a complete corpus one-pass screen). The [independent sparse far anchor scan](2026-10-19-sparse-far-anchor-screen.md) detected long file-wide repeats but did **not** integrate into JLZ, charge payloads or protect decode-worker independence. This new screen specifically tried **sparse exact far sequence insertion into existing match decisions within a single four-block group**, with the existing near-window 2-slot index still active, and bounded history fully resident in the already reconstructed group's decoder buffer. The new far index is keyed by native 8B source content sampled every 16B, requires at least 16 verified bytes and only competes on matches >=64 B; normal native match scoring and repeat cache, XOR/ADD candidate handling, and literal/length/distance packing remain active. Index positions and candidate scores are not serialized. No prebuilt codec or third-party compression logic.

## Preliminary original-source mathematical upper bound

A standalone original Go, independent anchor scan (not the codec) checked each of all 12 original full files, segmenting into 1MiB independent four-block groups. On 16B sampling and two prior 8-byte-key positions, it found up to **2,633,817 B non-overlapping verified exact source coverage** for matches with distance >128KiB, length >=64B, within groups. For the three historically mathematical-dominant files: **mozilla 768,169 B**, **ooffice 11,412 B**, **samba 411,183 B**. In contrast **nci 1,019,546 B** is largely BWT-selected in actual production. This is a gross *source-byte* ceiling, **not incremental JLZ compressed-size savings**, and source matching can duplicate matches already exploited by native near references, other modes, or entropy coding. Scan took ~0.77 s aggregate for all 12 loaded files (file reads outside per-file timer). Input Silesia SHA256 manifest check **12/12 PASS**, 211,938,580 B total.

## Full-codec disposable source implementations and results

Variant **G0**: For each native cross-group mathematical block beyond the first, pass all earlier **same-group** history. Keep near match buckets populated from the last 128KiB only, and build a separate sampled group-local older-history map; before standard original recent/exact/XOR/ADD candidates, optionally score a verified long exact match. Decoder supplies its *already reconstructed current group* rather than the prior 128KiB slice to the unchanged native exact-copy command decoder. The first complete original all12 JLZ1 encode/decode **reconstructed every file byte-exact** and produced **58,677,251 B (-90,488 B, better; -0.1540% compressed archive)**, 5.832769 s encode /1.987345 s decode single-pass diagnostic. Mozilla **18,368,427 B (-84,203 better)**, samba **5,127,971 B (-6,291 better)**, ooffice **2,692,258 B (+6 worse)**; remaining nine unchanged. This variant can alter a block's normal match-likelihood preflight and does slightly regress ooffice.

Variant **G1**: Add cheap current-block/older-prefix checked 64B exact-anchor gate (two sparse matches required), so full group history and far map are only constructed when source evidence warrants. Keep ordinary 128KiB history and entire existing parser when the gate fails. Evaluate transformed-match source evidence only over the 128KiB local part to avoid conflating far historical density with the already accepted near-index decision. Actual full original Silesia JLZ1 archive **58,681,409 B (-86,330 B, better; -0.14690% compressed archive)**. All 12 original full files byte-exact, checksum/format verified. **Mozilla 18,370,668 B (-81,962 better)**, **samba 5,129,894 B (-4,368 better)**, other ten including ooffice byte-identical size and format hashes. Decoder compatibility: new reader still accepts existing old 128KiB history and prior archive formats (targeted existing archive and legacy match mode tests pass); older existing reader **has not** been proven to accept new far distance commands. A newly encoded G1 archive that actually uses >128KiB references would require the candidate decoder, so treat as **forward-incompatible with the old decoder**.

## Validation and decision

Production source identity was checked against live `main` (docs-only intervening commits) at matcher/hash/gate and PGO blobs; source originated from the verified `8566c8a` ZIP. `go test -count=1 ./...`: **PASS**, `go vet ./...`: **PASS**, targeted engine `go test -race -count=1` covering group cross-reference, old-archive compatibility, corruption and concurrent paths: **PASS**. `CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build`: **PASS** (cross-build, no Windows runtime claimed). Corpus source identity **12/12 SHA256 PASS**. Full original 12-file G0/G1 roundtrips exact in all completed local passes. No new production archive writing or wire mode committed.

**Decision:** Defer this *same-group sparse 16B anchor and checked long-copy insertion* variant: actual 86KB gain over an already 58.8MB archive, conflicting paired compression-time signals, expanded decoder history contract, additional maps/copies and forward decoder incompatibility. **Do not reject Zstd LDM or the group-serial scheduling family wholesale.** Credible structurally different next study: precompute a bounded **group-level sparse sequence list once** and feed only verified anchors into parallel region jobs rather than independently building a map per block or duplicating gates; compare actual selected match stream bytes before format decisions, preserve exact/XOR/ADD and calculate encoder overhead. Do not rerun nearby anchor stride/window thresholds or ordinary 512KiB always-indexed history.
