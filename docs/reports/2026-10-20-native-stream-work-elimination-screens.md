## H1: direct column interpretation replacing synthetic native-token reserialization

**Placement:** existing selected mathematical match opcode/length/distance/transform/literal stream **decoder**. Closest prior: earlier combined reciprocal probability / direct L/M/D decoder candidate, rejected without a clean isolated performance qualification (ledger's historical combined screen). Here only the packed-mode decoder was changed. Existing `decodePackedWithLengthMode` unpacked five streams, serialized an ephemeral old-format archive with copied columns, then `decodeMatchNativeVariantHistory` reparsed it. A disposable Go implementation extracted the current native token expansion loop into `decodeMatchStreams`, called from both native and packed formats; it retains repeat-offset state, bytewise XOR/ADD references, optional residual literal interpretation, cross-group past history, opcode padding validation and bounds. No additional token search, wire mode or decoding method.

- Uncached `go test -count=1 ./...`, `go vet ./...`, and `CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build` **PASS**.
- Three PGO-enabled independent complete original twelve-file screens: **58,767,739 B each**, all twelve originals byte/SHA exact on every screen. First complete screen **6.042551414 s encoding / 2.059045566 s decoding**; next two **6.289214714 / 2.119301762** and **5.466746823 / 1.887880856**. An earlier *unprofiled* diagnostic **6.434582400 / 2.229464917** is not comparable with the PGO-equipped accepted build.
- Despite eliminating copies, the candidate screen did not demonstrate improvement over retained approved 4.7873709325 /1.8721679705 s. Timing environment is noisy/unpaired; do not claim a precise percent regression or a validated speedup. **REJECT integration; stop before a pointless ten-run series.** A full complete integrated screen was run, but NO ten-run candidate medians established. This result closes the *specific synthetic-buffer removal implementation*, not all decoder scheduling.

## H2: consume Go SA-IS suffix-array serialization as a streaming BWT sink

**Placement:** *BWT forward* suffix-order extraction/temporary buffers, no entropy/wire/decoder changes. Distinct from the prior radix prefix-doubling suffix-order *replacement*: retains Go stdlib's existing SA-IS engine and its emitted suffix order. Current `bwt.Transform` calls `suffixarray.New(input).Write(&bytes.Buffer)`, then scans the 10-byte framed serialized raw data and suffix offset records and builds the BWT last column. A disposable `io.Writer` consumed the exact length/source and independently framed offset chunks during `Index.Write`; checked every declared count and offset, emitted the BWT column directly and removed the single sentinel hole in-place. No giant serialized temporary buffer. Go's `Index.Write` chunking is implementation-specific and tightly validated; future Go versions could change it.

- Native Go `bwt` and engine package tests **PASS**. One original-corpus-specific component correctness test verified the **same BWT output and primary row on all 815 original natural 256KiB blocks** of the twelve complete source files, both routines run on every block. Alternated test order to moderate drift.
- Cumulative *BWT forward component* wall times on those 815 blocks: **existing 10.002696875 s**, streaming **9.911517818 s**, a marginal **0.912% component reduction**, not compressor speed. These timings include independent SA-IS calculations for both variants and are NOT ten full-JLZ benchmark runs.
- One PGO-equipped **complete original twelve-file integrated candidate screen**: **58,767,739 B / 5.300531860 s encoding / 1.921110508 s decoding**, all twelve full-byte and SHA reconstruction checks pass, exact per-file archived sizes unchanged. Reference historical accepted 4.7873709325 /1.8721679705 s, not rerun. No evident Pareto win on either runtime and only ~0.9% stage gain for extra writer/state/fragile serialization assumptions. **REJECT, no ten-run candidate.**

## H3: heap-based deterministic native finite-state frequency rounding

**Placement:** internal model-construction work of existing native rANS/FSE streams, no new model or bitstream. Existing `finiteStateNormalize` rescans 256 candidates for each deficit/surplus normalization correction. A disposable stack-fixed 256-symbol binary heap preserved all rounding tie rules: descending remainder then frequency then symbol index on deficits; descending normalized frequency then symbol index on surplus, with minimum-one enforcement. Cumulative frequencies and 4096-entry decoder lookup were built identically.

- Exact all-field match (frequencies, prefix sums, lookup tables, count) on all **815** original Silesia 256KiB **raw-source block histograms** and **300,000 seeded randomized count configurations**; randomized distributions are correctness fixtures, not benchmarking corpora.
- Alternating-order isolated model-construction screen, 100 repetitions of the 815 original-source block histograms: current **2.922466 s**, heap **1.180059 s**, checksum 68,553,400 and identical table bytes. Roughly **17.4 ms saved per 815 normalization calls**. Raw block histograms do *not* represent actual already-selected JLZ FSE symbol streams, and selected-stream call counts were not measured. This is NOT a complete JLZ archive candidate or a 10-run compression median.
- **DEFER**: model normalization is only a small portion of the encoder; adding heap code for a possible few milliseconds per corpus is not a substantial architectural improvement. Do not exaggerate isolated speedup as production throughput.

## Outcome and genuinely distinct queue

No permanent source changes, no accepted H1/H2/H3. The existing archive, decoder grammar, root PGO, CLI and main's two commands remain unchanged. Avoid further iterative threshold/heap/buffer micro-tuning on these placements.
