# Round 36: Speed-first local prototypes, complete Silesia candidate benchmark

**Date:** 2026-10-19. **Decision: REJECT 72 KiB arithmetic-literal cutoff; do not promote the other screening prototypes.** Approved native JLZ engine remains Round 29. Research-only changes were discarded locally. No new compressor source is committed. GitHub Actions were not used.

## Environment and scope

The uploaded public `jlz-main.zip` corresponds to commit `708f864`. Locally applied the already-committed fixture path fix from `28865fb`, then validated the clean Go 1.23.2 linux/amd64 source with `go test -count=1 ./...`, `go vet ./...` and Windows/amd64 cross-compilation. Extracted the exact original 12-file Silesia ZIP (211,938,580 bytes), and verified individual source SHA-256s during candidate tests. No external compression backend was used. Historical JLZ, Zstd and XZ references were reused, never rerun.

This round's target was to reduce *compression* latency while preserving near-Zstd-3 archived bytes. A CPU profile from a candidate-only full Silesia screen (not a retained baseline timing) placed about 24.5% of sampled CPU time in native tokenization, 19.3% in BWT transformation, 18.1% in adaptive arithmetic encoding, and 15.3% in arithmetic decoding. These percentages are cumulative across concurrent execution and decode/encode combined, not directly additive wall-time improvement estimates.

## Implemented and tested prototypes

1. **Adaptive match-search skipping**, independently inspired by Snappy's strategy: index all intervening input positions, but probe fewer candidate starts after repeated failed matches; skip the one-byte lazy lookahead for strong matches. Mild skip (up to eight positions, miss count /64, lazy threshold 64) completed one full 12-file screen: **62,499,956 bytes, 7.966848 s encode / 2.822271 s decode**, 12/12 exact source restorations. Aggressive skip (up to 32 positions, miss count /8, lazy threshold 32) completed a separate full screen: **62,616,747 bytes, 7.953663 s / 2.874871 s**, exact. Neither demonstrates a meaningful encode-speed win against retained 7.516364 s, and both are single-screen measurements from an independent session. Not promoted.
2. **Exact fixed-point arithmetic probability**: attempted Q32 reciprocal lookup and one-step exact rounding correction for the context arithmetic coder. An exhaustive correctness test for all frequencies with totals 1..2048 passed, as did Go unit tests and one whole-Silesia roundtrip screen. Screen: **62,494,395 bytes, 9.607233 s encode / 3.300912 s decode**. The archive-size difference from the historical approved reference was unexpected despite bit-exact probability equivalence and warrants separate source/byte audit; do not treat it as a verified codec ratio improvement. Unfavorable CPU evidence; discarded.
3. **Exact-reference-only mathematical regions:** removed XOR/ADD match probes in independently coded regional blocks while preserving the direct tokenizer. One full Silesia pass produced **62,518,675 bytes, 8.028103 s / 2.978064 s**, exact roundtrips. One existing regional-mode selection regression test failed, so this change is rejected independently of timing.
4. **Context arithmetic cutoff**, replacing the original 256 KiB eligibility ceiling for `packLiteralStream`: completely removing the arithmetic path failed two intentional format/selection regression tests. A 128 KiB cutoff passed Go tests but screened at **62,702,946 bytes, 8.757583 s / 2.939810 s**. The 72 KiB cutoff passed the unchanged Go test suite and screened at **63,329,487 bytes, 7.777009 s / 2.284659 s**. The latter warranted ten full candidate-only encode/decode runs to characterize its decode-speed tradeoff.

**Decision: REJECT the 72 KiB cutoff for the present speed-first objective.** It produces a substantial *decode*-time reduction but does not show a material *encode*-time improvement, and makes the archive 684,824 bytes larger. Differences between independently timed machines/sessions are directional, not a paired measurement or proof of a causal small encode regression. Zstd/XZ CLI numbers include different I/O/process conventions and are not directly comparable with JLZ's in-memory results. Historical per-file archive sizes and the uploaded source snapshot are not assumed to be a paired byte-identical baseline; no new baseline measurement was made.

**Validation after rollback:** removed all trial encoder changes and temporary benchmark test; clean original source (plus already-promoted fixture fix) passed `go test -count=1 ./...`, `go vet ./...`, targeted race tests including BWT/additive/native concurrency, and `GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build`. New feature packages and the Windows cross-build are confirmed compilable. No candidate code was committed.

## Next priorities

Optimize arithmetic-literal coding by a **cheap, selected-stream-aware preflight** or a demonstrably faster exact arithmetic implementation, so the 22% decode-speed opportunity does not require a 1.09% whole-corpus archive-size regression and neutral encoding. Quantify the actual selected per-file arithmetic literal contribution, and avoid expensive BWT/transform work only when defensible from input samples. Maintain original full-Silesia-only benchmark requirement and ten-run candidate-only promotion criteria.
