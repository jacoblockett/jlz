# Round 16: Operation-conditioned length streams (accepted)

**Date:** 2026-10-18. **Base:** approved Round 15 (`66,797,408` bytes). **Decision:** ACCEPT after exact reconstruction, paired compression and decoding benchmarks, and correctness tests. All persistent edits land directly on `main`.

## Hypothesis and implementation

Match-token literal-run lengths and reference lengths have meaningfully different distributions. Their old concatenated varint stream uses one Huffman model. The experiment retains the same token parser, references, literals and checksum, but encodes **literal and copy lengths in separate streams**, selected internally only when the complete new metadata header is strictly smaller. Shared operation, distance and transform payloads are packed once, so no second match search is introduced. Old packed block types remain decodable. Two new mixed-block types represent normal/predicted literals with split lengths. No user-selectable mode, no external backend, no compression-level option.

New archives containing split-length blocks **cannot be read by the old Round 15 decoder**. The Round 16 decoder reads both old and new JLZ1 blocks. This is a compatibility distinction, not a new file extension or user mode.

## Complete Silesia benchmark

Input: twelve original Silesia files, **211,938,580 bytes**. Baseline and candidate built from the approved Round 15 source, with the candidate difference limited to conditional token-length encoding and its decoder. Same host and Go toolchain, ten paired runs in alternating order, full 12-file in-memory compression/decompression timing, medians of ten. Raw run records retained in the adjacent CSVs.

| Metric | Round 15 | Candidate | Relative change |
|---|---:|---:|---:|
| Complete archive bytes | 66,797,408 | 66,519,205 | **0.42% smaller** |
| Median encode seconds | 13.874 | 13.290 | **4.21% faster** |
| Median decode seconds | 5.493 | 5.311 | **3.31% faster** |

These medians differ from older reports because the test host is not controlled against historical environments. Reuse old external comparator results as size references only: **Zstd-3 66,216,569 bytes, 1.256 s historical CLI encode**; **XZ-6 49,233,340 bytes, 116.989 s historical CLI encode**. CLI timings are not comparable to the paired JLZ in-memory medians.

## Validation and scope

- Full Silesia 12/12 byte-exact roundtrips for the benchmarked candidate, with a fresh full-corpus rebuild reproducing **66,519,205 bytes**.
- Bundled fixture and regular uncached Go tests (`go test -count=1 ./...`) passed.
- `go vet ./...` passed after removing a redundant decoder self-assignment.
- Targeted race-instrumented tests passed (`TestJointTokenLengthsRoundTrip`, `TestCrossGroupReferenceAndCorruption`, `TestJLZBundledFixtureRoundTrips`). Not claiming an exhaustive full race suite.
- New decoder read full previous-version Silesia archives successfully; an explicit split-length test confirms correct reconstruction and rejects truncated streams.
- Linux/amd64 local build passed. Cross-platform deliverable verification belongs to the repository Test workflow. No precompiled binaries committed.

## Conclusion and next step

Promote on `main`: all three aggregate metrics improve. Although the **0.42%** size change is below the skeptical 3% threshold, the **4.21%** encoding and **3.31%** decoding improvements justify the limited, measured format extension. Do not extend the design speculatively to additional token partitions without evidence. Next: investigate a genuinely unified token/entropy cost model, considering the distribution of copy lengths, distances and operation types in a single inexpensive pass, rather than a second matcher/grammar scan.
