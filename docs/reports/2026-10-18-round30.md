# Round 30: Rank-two additive progressions and finite-group doubling (rejected prototype family)

**Date:** 2026-10-18. **Approved JLZ remains Round 29.** All candidate code was implemented in a disposable Go 1.23.2 local copy; no encoder/decoder/archive-format changes were promoted to `main`. All performance research used **only original Silesia**; no prior JLZ or external-compressor full-corpus benchmark was rerun.

## Why this theoretical family

Round 29 demonstrated a real but narrow 16-bit modular additive-word representation. The user requested substantial follow-through on **theoretical catalog ideas**, not dismissal from old negative prototypes. This round examined structures involving **two independent additive generators** in the finite group Z/(2^16), genuinely executable 2D reconstructions, and a bounded exact additive doubling calculation. **This is a finite implementation inspired by generalized arithmetic progressions and low-doubling structure, not a full Polynomial Freiman–Ruzsa algorithm, proof, or disproof.**

All the following representations were **implemented with Go encoders and decoders** (not just entropy estimates). The input is arranged as little-endian 16-bit original words; odd trailing bytes are restored. Payload sizes below use JLZ's existing native raw/RLE/Huffman packed streams and charge the candidate's actual metadata, but **do not include JLZ1 file headers, original-file SHA-256, or mode headers**. These are **component sizes**, not complete JLZ archives.

## A. Rank-two two-dimensional modular mixed difference

Interpret a block's words on a 2D grid of width W, testing W=2,4,8,16,32,64,128,256,512,1024,2048. Interior mixed difference in Z/(2^16):

`d[r,c] = x[r,c] - x[r,c-1] - x[r-1,c] + x[r-1,c-1]`.

The first row uses a left-neighbor difference; first column uses the previous-row difference. Signed zigzag maps 16-bit differences to nonnegative 16-bit symbols; its low and high bytes are independently entropy packed. The **width is serialized as two bytes**, and unmatched input tail is stored. The decoder reconstructs row-major by adding already recovered left/top and subtracting top-left. All widths of all 36 representative first/middle/last Silesia regions roundtripped exactly; additional odd, zero, and random lengths passed.

Some `mr` sampled regions preferred a width of 512 16-bit words and saved 1,770 / 7,074 B compared with Round 29's one-dimensional additive payload; `x-ray` got **worse** by 6,483 / 5,411 / 2,033 B.

## B. Explicit two-generator affine grid plus exact residuals

Encode each word as:

`x[r,c] = base + r*g_row + c*g_col + residual[r,c] (mod 65536)`.

Pick `g_row` and `g_col` as modal observed finite differences from a bounded grid-position sample; serialize 16-bit width, base, and both generators (**8 bytes of model metadata**). Signed-zigzag and native entropy coding describe every exact residual. The decoder evaluates the same formula, reconstructs exact original words, and preserves odd tails.

All 36 original-byte Silesia sample regions roundtripped for each of eight tested grid widths, as did adversarial small/random/affine synthetic *correctness* fixtures (not separate performance corpora). Gains compared with one-dimensional coding occasionally occurred, especially a first `mozilla` sample, but **did not beat the existing native BWT competitor**.

## C. Two-generator additive walk with explicit exceptions

Compute original modular word differences. Select the two most frequent nonzero 16-bit differences, `g1` and `g2`, from within each sample region. A step can be one of the **nine** signed additive combinations `{0, ±g1, ±g2, ±g1±g2}`; otherwise encode operation `9` and carry the **exact 16-bit exception** in two native packed exception streams. Charge **six bytes** for the two generators and initial word, plus actual packed operation/exception stream frames and odd-tail bytes. The decoder uses the recorded operation and exact exception to reconstruct every source word in order. This represents an explicit limited rank-two additive generating set with fully priced exceptions rather than mere rearrangement.

All 36 Silesia samples and adverse-length/random/affine correctness fixtures decoded exactly. Samples of `nci` improved against one-dimensional additive coding by 19,820 / 19,704 / 19,745 B, but native BWT compressed those same three samples much more strongly.

## E. Bounded exact group-theoretic additive doubling

To probe the premise that natural source 16-bit values inhabit a low-doubling subset, selected up to the **first 128 distinct words** per region and explicitly enumerated the sumset modulo 65,536, recording `|A+A| / |A|`. This computes an exact group-theoretic statistic for the chosen bounded subset, but is **a biased truncated sample** and not the doubling constant of the full file's set or an implementation of the PFR theorem.

Most 128-element samples had doubling ratios roughly 20–60. A few were exceptionally structured: last `mr` sample had only 12 distinct words and ratio **1.92**, final `ooffice` ratio **1.99**, middle `x-ray` ratio **3.41**. Those cases still did not yield a rank-two packed representation outperforming the incumbent sample codec. Low doubling by itself is not an archive-size claim.

## Verification, benchmarks and decision

- Disposable source in `/mnt/data/jlz-round30/ranktwo_research_test.go`: actual reversible encoders/decoders for all three variants and native packed stream sizes. Not committed as dead production code.
- All 36 original Silesia sample regions passed per-width 2D/affine and per-generator exact original-byte comparisons.
- Random, short, empty, odd-size, modular-grid fixtures verified decoder inverses independent of performance claims.
- `go test -count=1 -run '^TestRankTwo(...)$' ./...`, `go vet ./...`, and targeted `go test -race -count=1` all **PASS**. No production source edit or compatibility change.
- **No fully integrated candidate and no ten-run whole-Silesia candidate benchmark**. Thus no model-row full-archive results or percent timing deltas exist for Round 30; current approved Round 29 remains **62,644,663 B**, candidate-only historic median **7.516364 s encode and 2.821363 s decode**.
- Historical complete Silesia reference archives and timings reused **without rerun**: Zstd-3 66,216,569 B, CLI encode 1.2561 s / decode 0.8551 s; XZ-6 49,233,340 B, CLI encode 116.9892 s / decode 2.3079 s. CLI and JLZ timing methods are different.
- **Decision: Reject these three finite rank-two prototypes for JLZ promotion**, **not** the generalized additive combinatorics theory. Their best selected regions still lose to JLZ's already implemented options. A new block mode, expensive full-corpus encode and ten candidate runs are unwarranted.

**Next catalog priority:** examine geometric/CAT(0)-inspired boundary-distance representations with a genuinely invertible grid-boundary encoder, not simply substitute another byte-lane Huffman context. Maintain theory/implementation distinction and record both successes and failures.
