# Round 21: Automatically gated native BWT regions (accepted)

**Date:** 2026-10-18. **Base:** approved Round 16. **Decision:** **ACCEPT** after ten paired full-corpus encoding and decoding runs, byte-exact 27-file compatibility audit, uncached Go tests, vet, and targeted race tests. All persistent work goes directly to `main`; the sole exceptional Git branch is the ephemeral `jls-test/*` CI trigger.

## Structural hypothesis and new implementation

Round 18–20 established that further entropy-weight adjustments could plausibly save only tens or hundreds of kilobytes. A new **automatically selected block-sorting representation** can make structurally different progress on the original input *before* the mathematical matcher tokenizes it:

1. For selected 256 KiB input regions, compute a reversible **Burrows–Wheeler transform (BWT)** using Go standard-library `index/suffixarray` sorting. Store the unique sentinel's primary row so all 256 byte values remain invertible.
2. Apply a **move-to-front rank transform** and bounded zero-run varints, then use JLZ's **existing native raw/RLE/Huffman stream selector**. This does **not** call bzip2 or any mature compressor backend; BWT, MTF and Huffman are established techniques and are **not claimed as new mathematical discoveries**.
3. Reuse the already evaluated first/middle/last mathematical-region samples. Encode their alternative BWT representations once. Only choose the full BWT architecture if **at least two of three samples win** and total BWT sample payload is **at least 5% smaller** than existing region payloads. Reuse those 3 serialized BWT blocks; parallelize the rest over automatically available CPU workers. Files without strong evidence remain on Round 16's exact established coding paths.
4. Keep the `JLZ1` container, SHA-256 integrity, bounded region size and user interface unchanged. Add only one internally selected `modeMixedCross` block type (`blockBWTPacked = 12`). Decoding is reversible with the sentinel row, MTF zero-run reversal and LF mapping. No user level, option or third-party backend.

**Engineering caveat:** The standard-library suffix-array index does not expose ranks directly. The encoder reads the implementation-specific `Index.Write` output (10-byte prefixed length, input copy, varint suffix indices) with explicit prefix and bounds validation. All production output is independently decoded using JLZ's own BWT inverse, and unit tests exercise it with the current Go toolchain; CI must independently verify the supported platform matrix. If Go changes the internal serialization, its producer must fail closed or be replaced with a self-contained suffix-index enumerator; do not silently rely on future wire-layout compatibility.

### Complete compatibility and safety audit

Audit records: [`2026-10-18-round21-archive-audit.csv`](2026-10-18-round21-archive-audit.csv). **27/27** original inputs (12 Silesia and 15 diverse fixtures) roundtripped byte-exactly with the new decoder. The Round 21 decoder successfully reads **27/27** Round 16 archives. Old decoders read **21/27** new archives unchanged and **correctly reject the six new BWT block archives** (old-version decoder cannot decode a format extension; never imply forward compatibility). All 15 fixture archives and six other Silesia archives remain byte-identical to Round 16. The complete 12-file candidate archive rebuilt identically at **63,770,766 B**.

Full `go test -count=1 ./...`, `go vet ./...`, and targeted `go test -race -count=1` on BWT roundtrips, cross-group references and fixture roundtrips **passed**. No comprehensive race suite is claimed. Automated GitHub Actions multi-platform validation and release publication are tracked separately by the Test workflow.

## Negative subprobes that shaped the design

A diagnostic mature block-sorting comparator on *already-selected literal streams* yielded only **194,603 B** aggregate savings (39,562,459 B of selected literals, 750 streams), insufficient to justify an extra compression layer **after** match parsing. This comparator was **diagnostic only**, never a JLZ production encoder. In contrast, native BWT/MTF/Huffman on **original input regions**, chosen *instead of* running mathematical match parsing, proved viable. Using native block sorting indiscriminately would save under 1 MB on selected group payloads and regress badly on Mozilla/Samba. A hypothetical perfect per-block post-hoc choice could save ~3.03 MB but requires both complete encodes. The 3-sample, 5%-margin file-level gate obtains a measured 2.75 MB complete-archive gain **without** double-encoding all regions.

## Decision, retained constraints and next experiments

**PROMOTE Round 21 as the canonical approved source.** All three aggregate metrics improve substantially, no file grows, and decoder/corpus compatibility was verified. Code change is limited to the new native BWT region implementation/tests, a conservative selector in `region_first.go`, and a decoder dispatch in `cross_region.go`. No binaries or corpus files committed.

Research follow-ups: check generalization on legally reusable non-Silesia inputs; measure memory peak and rare high-entropy/abnormal-block behavior; review whether suffix-index serialization coupling merits a simpler self-contained enumerator **only if required**. Avoid overfitting thresholds, re-running marginal entropy-weight sweeps, or adding user-selectable compressor modes. Keep YAGNI and explain bitstream invariants in source.
