# Native four-state rANS with compact bitmap model headers, 2026-10-20

**Status:** REJECT concrete integrated H1 and H2, SCREEN/REJECT their work-elimination follow-ups H3/H4 and unrolled decoder H5. **No production source promoted, root PGO unchanged.** The accepted JLZ remains **58,767,739 B / 4.7873709325 s encode / 1.8721679705 s decode** on the **complete original 12-file Silesia** (211,938,580 B; accepted ten-run medians). This research is a new **entropy representation**, not a repeat of previously rejected streamed suffixarray writer, four-hop LF inverse, or three-context predecessor-conditioned rANS.

## Primary-source investigation and distinction from historical modes

Inspected actual [Apple LZFSE finite-state coder](https://github.com/lzfse/lzfse/blob/master/src/lzfse_fse.c), its [base encoder](https://github.com/lzfse/lzfse/blob/master/src/lzfse_encode_base.c) and [Zstd sequence-model and table-cost implementation](https://github.com/facebook/zstd/blob/dev/lib/compress/zstd_compress_sequences.c), then current `engine/finite_state.go` and `engine/stream.go`. Apple uses its own tANS machinery; these sources are **architectural research references only**, not imports, existing-code ports, executable dependencies, or JLZ compression backends.

JLZ already has a **single-state 12-bit native rANS** codec5 per selected metadata/BWT symbol stream, transmitting a sparse normalized model as `count varint; count × (symbol byte, normalized-frequency varint)`. Earlier failed three-table predecessor-conditioned rANS switched context models *per symbol*; the present experiment instead keeps **one identical model**, but tracks **four independent byte-rANS coding states** indexed by `symbolPosition % 4`, enabling instruction-level parallelism without per-symbol context switching. It changes neither the BWT transform, MTF/zero coding, nor math match search.

An original **256-bit symbol bitmap** replaces the explicit symbol labels in high-alphabet tables, followed by only the existing normalized frequency varints. The sparse table sum and all 4,096 model lookup states are reconstructed deterministically and bounded during decoding. The new disposable packed-stream subtype6 retains the original raw decoded stream length and payload frame, and dispatches to either one-state or four-state decoding depending on candidate; existing stream codecs0–5 and archive modes remain readable. Newly encoded subtype6 is not readable by an older JLZ binary.

- **H1: four-state + bitmap.** Use four-state rANS and compact bitmap automatically on high-alphabet data (>=60 occupied symbols), otherwise legacy single-state. Compete against the incumbent raw/RLE/canonical Huffman envelope, with actual lengths and all additional state words charged; no extra full second rANS encoding.
- **H2: single-state + bitmap.** Keep the exact incumbent native rANS state transitions and four-byte initialization, but replace only its sparse frequency header when >33 symbols. Guarantees that the entropy-table portion does not expand relative to the prior codec5 for the *same* encoded bytes. Both candidates are **supplements** of existing JLZ streaming entropy representations, not stand-alone codecs.
- **H3/H4: optional exact Huffman lower-bound preflight.** Construct candidate FSE output first, use the zero-order Shannon lower bound on any Huffman bitstream plus its mandatory full sparse-table byte count, and skip `packStream` when the new fully framed candidate is provably cheaper than both Huffman and raw. Include 2-byte downward allowance against floating-point inaccuracies; uncertain cases fall back to the actual `packStream` comparison. H3 layers on H2; H4 layers on H1. This deliberately revisits **work-elimination in a different placement** from the earlier rejected FSE early-abort (which skipped losing FSE, whereas the current alternative avoids losing Huffman construction).
- **H5: unrolled four-state decoder.** Unroll four independently dependent rANS symbol steps, allowing simultaneous model lookup and state arithmetic; unchanged H1 emitted stream, and exact validation of trailing bytes/final state.

The independent stage screen measured four-state body-only byte lengths 3,189,468 B against original single-state 3,189,088 B **(+380 B, worse)**; frequency-table replacement, not magical improved byte entropy, is responsible for the net savings. ## Validation and decision

All **12 canonical Silesia SHA-256 manifests matched**. H1/H2 full uncached Go suite `go test -count=1 ./...`, `go vet ./...`, targeted `go test -race -count=1 ./engine` (finite-state tests; H1 also full 36-block native BWT test), and Windows/amd64 CGO-off cross-build **PASS**. H3/H4 full uncached Go suite PASS. Backward decoding separately verified: two complete *accepted-baseline* original Mozilla/Sao archives decoded via BOTH H1 and H2 candidate decoders with original byte-for-byte comparison (**4/4** PASS). Full exhaustive corrupt/truncated subtype6 fuzz testing, native Windows execution and entire-Silesia race build were not performed; standard built-in corruption checks and existing tests passed. Rejected prototype tests/source lived in isolated local directories and are not committed.

**REJECT the tested integrated four-state and bitmap coder variants**: 0.044–0.049 percentage-point compression improvement is reproducible, but neither demonstrates a whole-codec encode or decode gain against retained accepted reference. The additional packed-stream subtype and table normalization work are unjustified by these measured gains, despite a faster isolated state decoder. **Reject H3/H4** early because they did not rescue encoder performance; **reject H5 as a complete-codec improvement** based on two unfavorable passes despite strong stage-only results. The wider theory of compact model headers and independent entropy states is not logically disproven. Do not tune the number of states, bitmap thresholds, or repeat four-state unrolling. Instead locate architecturally different reductions of dominant mathematical-literal arithmetic or matcher work/bytes, with at least a substantial source-component win first.

**Current on `main` unchanged:** original JLZ 58,767,739 B / 4.7873709325 s encode / 1.8721679705 s decode; root profile and backward decoding preserved.
