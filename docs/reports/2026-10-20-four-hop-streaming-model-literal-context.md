# Four-hop BWT inverse, previously rejected streaming writer recovery, encoder-only finite-state table, and literal context split

**Date:** 2026-10-20. **Decision:** REJECT the concrete integrated variants and the sampled literal split. No production Go code, decoder mode, archive bytes or root `default.pgo` changed on `main`. This is an explicit follow-up to [the ten-run streamed suffix-index writer report](2026-10-20-streamed-bwt-suffix-index-screen.md) and its prior [all-block writer screen](2026-10-20-native-stream-work-elimination-screens.md), **not** a newly discovered streamed suffix-array mechanism.

## Source inspection and mechanisms

Studied actual upstream [Zstd histogram/model-building code](https://github.com/facebook/zstd/blob/dev/lib/compress/hist.c), [Zstd normalized-count cost code](https://github.com/facebook/zstd/blob/dev/lib/compress/zstd_compress_sequences.c), and previously source-reviewed [libbsc native BWT implementation](https://github.com/IlyaGrebnov/libbsc/blob/master/libbsc/bwt/bwt.cpp), comparing them to current JLZ `bwt/transform.go`, `engine/finite_state.go`, and mathematical literal model wiring. These were research references, not JLZ backends or imported/transliterated code.

1. **Q4 (new decoder-side hypothesis).** Current accepted JLZ BWT inverse precomputes a 64-bit 2-hop LF cell (two 9-bit symbols and successor row) for every row; independently tested four successive LF transitions per 64-bit cell, four 9-bit symbols plus the successor row. This genuinely changes inverse dependency depth and is unlike the old failed one-hop packed LF and the earlier accepted 2-hop inverse. It preserves all source, archive and forward encoder bytes. Four-hop precomputation performs extra dependent LF reads but halves the final inverse-loop table lookups vs 2-hop. Input validation includes the virtual sentinel.
2. **FSE-no-lookup (new encoder-work hypothesis).** An encoder-side model need not populate the 4096-entry symbol-lookup array; that array is used only by the inverse finite-state decoder when reading the transmitted frequencies. The standalone trial added an encoder-only normalization path, preserving the legacy full table path for direct decoder/model APIs. Normalization, cumulative frequencies, exact coding states and framing were otherwise identical. This removes pointless writes but adds a second normalization entry point.
3. **Writer-recovery integration (replication, NOT new).** Restored the already screened native `suffixarray.Index.Write` chunk-consumer, checks source/header/chunk sizes and suffix offsets, writes last column directly without retaining the serialized temporary buffer. Combined this with FSE-no-lookup and Q4 into a second full-corpus candidate. This tests whether complementary decoder work and encoder work reduction can rescue the writer's historical regressions, rather than treating its earlier unpaired decoder timing gain as causal.
4. **Literal-run boundary context (new source-model component screen).** Inspired by the principle of match-conditioned literal coding in LZMA, partition actual currently produced mathematical-token literal bytes into the first literal after each match and the rest of the literal run, identified entirely from already serialized opcode and command-length streams. Encode the two actual native JLZ arithmetic/stream frames, charge a one-byte selector and a count varint, and independently reconstruct the exact literal sequence. This is supplementary to current math token selection, not a replacement compressor. The sample result was far too small to warrant a decoder mode or integration.

**Important causality:** The previous streaming BWT candidates changed *only forward encoding*. They **cannot causally reduce decode work for a byte-identical archive**. Their historical 4–6% lower independently measured decompression times were not a real decoder improvement. Q4 is the first trial here with an actual decoder change.

## Validation and decision

- Exact original input SHA-256: **12/12**. Ten complete runs per integrated candidate: **120/120 exact reconstructed originals each**, deterministic size; 12/12 complete serialized archive SHA-256 identical to current accepted source in separate correctness run for both.
- Combined and Q4: `go test -count=1 ./...`, `go vet ./...` PASS. Combined targeted `go test -race -count=1 ./bwt -run 'Test.*(TwoHop|Bijective|MTF|BWT|Inverse)'` PASS, `CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build` PASS. Windows actual runtime untested.
- The full prior archive compatibility suite was included in uncached Go tests, but **no separate retained full historical .jlz archive was decoded during this experiment**. No new archive mode was introduced, and bitstreams were SHA-identical.
- Standalone FSE path passed targeted finite-state tests and three full original-source exact screens; **not** ten-run qualified. Literal-head/tail component inverse and framed native packing 18/18 PASS; no integrated decoder/test/ten-run attempted.
- Reverted all disposable test and trial code by not promoting it; no production Go files or PGO changed on GitHub.

**REJECT Q4 and recovered streaming-writer+FSE+Q4 concrete implementations**. Keep the accepted 2-hop LF inverse, current suffixarray temporary serialization and existing FSE model path. **CLOSE** four-hop LF stage under this precomputation arrangement, the already screened streaming writer path and encoder-only lookup micro-optimization until a fundamentally different algorithm or matched-platform evidence appears. Do not re-tune hop count or contiguous literal head/tail thresholds. **NEXT:** prioritize major ratio/runtime architectural gains in actual Mozilla Alpha COFF mathematical regions, e.g. share original match-token discovery while using a lightweight code/noncode classification *within currently selected native literal streams*; avoid reproducing the rejected twice-encoded whole-file COFF partition mode.
