# Round 29: Native modular-additive word progression (accepted)

**Date:** 2026-10-18. **Decision:** ACCEPT a limited, completely reversible, original-byte, native JLZ implementation of a one-dimensional additive-progression representation. This is **not a full implementation or verification of the Polynomial Freiman–Ruzsa theorem**. Its richer rank-two/general additive-structure investigations remain open on the active theory backlog. Production source committed directly to main, no persistent experiment branch, no existing compressor backend.

## Experimental hypothesis and what was actually implemented

Treat consecutive little-endian 16-bit input words as a walk in the finite additive group Z/(2^16). Represent each word as the preceding word plus a modular signed difference. Test an explicit modular constant-drift model and second-order finite differences (locally reversible but generally uncompetitive); then encode signed modular differences with a reversible zigzag mapping, independently packing the low and high bytes using JLZ's *existing native Huffman/RLE/raw entropy coder*. The final block payload begins with format-identifying byte 4, two independently framed native streams, and the unmatched last byte when the region size is odd. Decoder reconstructs words in original order, bounds stream lengths, requires exhaustion and checks the complete original-file SHA-256.

This constitutes a working **rank-one local additive encoder and decoder**. It does not discover arbitrary generalized arithmetic progressions, calculate low-doubling sets over Silesia, or establish the PFR conjecture. It differs materially from rejected historical byte-lag/XOR prototypes: word-sized modular arithmetic on actual original-source 16-bit fields, bit-exact serialization, and full-file standalone JLZ integration.

The candidate competes only after the existing Round 25 BWT preflight succeeds. A cheap sampled structural gate requires at least two of the first/middle/last 256 KiB regions to have 75% or more adjacent 16-bit word differences within -128..127. Then three **actually serialized** candidate stream sizes must win at least two individual BWT probes and by 2% in aggregate. The selected full-file encoding uses independently packed 256 KiB regions, parallel workers, existing JLZ1 modeMixedCross framing and a new internal block type **14**. For each region, raw fallback wins if it is smaller. It is one fixed automatic algorithm, no extra CLI option. Original SHA-256 is unchanged.

## Screening evidence and decision to construct complete codec

Tested all 36 representative 256 KiB sample regions of the twelve original Silesia sources. Three reversible coordinate prototypes (zero drift, modal constant drift, second finite difference) were coded in disposable Go sources and individually reconstructed byte-exactly. With the first variant, only sampled x-ray substantially beat existing BWT: 140,664/145,375/44,149 B versus 144,511/151,164/46,114 B for three original-source regions. A further **implemented** signed zigzag mapping improved the three new candidate packed sizes to **132,390 / 136,961 / 40,922 B**, each below corresponding BWT. Other files retained superior existing methods. All sample results include native entropy codebooks/framing, unlike pure Shannon bounds.

The first full 12-file integrated archive pass with unzigzagged word differences produced 62,913,808 B, down 190,309 B from approved Round 25, and passed exact restoration. The zigzag candidate produced **62,644,663 B**, saving 459,454 B; this full size was repeated exactly in all ten promotional runs. A generic inexpensive numeric-structure preflight reduced unnecessary entropy probes and preserved all twelve complete archive sizes. Experimental unused predictor modes were removed from production source.

## Verification and compatibility

- **12/12 complete Silesia original-byte roundtrips** pass, including each of ten candidate-only runs and SHA-256 equality of the original and restored x-ray source.
- Existing **27/27 approved Round 25 archives**, retained from previous audits, are decoded exactly by the new candidate decoder; **27/27 new archives** roundtrip. **26/27** candidate archives are byte-identical to previous Round 25 output.
- The previous Round 25 decoder correctly rejects Round 29's new x-ray archive with "cross block mode". This is a documented forward incompatibility of earlier decoders, **not** a loss of Round 29 backward-decoding support. New block type **14** is required for that file.
- Uncached Go tests and vet passed on the final source without temporary research tests; targeted `go test -race -count=1` for additive/cross/lane paths passed. Length/odd-size, random, low-variance arithmetic progression and corrupt-header/payload tests passed. The GitHub Test workflow is independently invoked after main synchronization.
- Only original 12-file Silesia used for **performance research**. Bundled 15 short project fixtures are used for correctness/compatibility auditing only. No non-Silesia benchmarks, no repeated accepted-JLZ or Zstd/XZ benchmark runs, no downloaded compressors or copyrighted inputs committed.

## Recommendation and next actual theory

**ACCEPT Round 29**, primarily because complete archive bytes improve 0.728% without demonstrated meaningful CPU regression and the code remains narrow, reversible, source-native and automatic. Avoid overstating sub-one-percent timing deltas across independent sessions. Recognize that Round 25 decoders cannot read new x-ray mode 14 blocks.

Update the theoretical ideas queue: a **rank-one modular-additive implementation is built and promoted**, but the **full PFR/additive-combinatorics family is OPEN**. Next test materially higher-rank generalized arithmetic progressions / low-doubling sets, with complete model and exception costs and held-out original Silesia evidence, rather than merely tuning this gate. Other unopened user catalog theories (full PID, CAT(0), prime-factor bases, unsimplified algebraic minimization) remain active. No theoretical impossibility has been inferred from rejected finite prototypes.
