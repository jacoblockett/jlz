# Engineering and acceptance contract

- **Branch discipline:** commit all lasting changes directly to `main`. `jls-test/*` temporary dispatch branches are the only normal exception. Keep isolated trial changes outside the repository until validated; no persistent experiment branches.
- **YAGNI**: no speculative flags, modes, abstraction layers, extra file formats or large experimental subsystems without demonstrated need. One automatic algorithm; only two verbs. Remove rejected candidate code from approved build.
- Explain all non-obvious arithmetic, overflow invariants, bit serialization, concurrency bounds and backward-format requirements with concise inline comments. Comments describe **why** and safety constraints, not paraphrases of obvious code.
- Byte-exact losslessness applies to original encoded file bytes (not merely equivalent media pixels/audio). Full archive bytes include headers and metadata. Never measure partial inputs or diagnostic backend compression as a standalone win.
- No third-party compressor backend, fallback, nested library encoder or optional existing-codec mode. Go standard library is allowed for general utilities but not `compress/flate`, `compress/gzip`, `compress/zlib` or external codecs in the compressor. External Zstd/XZ only for separate reference measurements.
- Continue to decode existing `JLZ1` archives when changes permit. New representation bits require a documented compatibility plan and forward/backward decoder evidence. Files from MDC/MDN must not be silently accepted.
- CPU resources: worker count is determined dynamically from CPU/cgroup limits and parallelizable blocks, with no fixed five-worker ceiling. Bound memory usage; explain tradeoffs.
- **Verification before merging:** `go test -count=1 ./...`, `go vet ./...`, race tests for affected concurrency code, 12 complete Silesia file roundtrips, 15 bundled fixture roundtrips and archived-byte equality where format-preserving. Record any suite not run and any failure.
- **Benchmark scope and reuse (latest user directive):** run compression benchmarks **only on all twelve complete original Silesia files**, totaling 211,938,580 B. All older non-Silesia corpus results are archived context, not approval for new benchmarks. Retain correctness/unit fixture testing. **Benchmark only candidate builds**, reusing the approved Round 25 (or latest approved successor) size and ten-run encode/decode medians, and fixed established Zstd/XZ reference results; no redundant baseline or external compressor reruns. Measure ten candidate whole-Silesia runs when a screen warrants promotion. Comparisons against historical reference runs are **not paired**; explicitly note timing/host uncertainty and avoid claims of controlled paired performance. Include per-file/worst-case regressions when available. Do not cherry-pick sampled portions as full-corpus results.
- **User reporting contract:** primary table rows, in order: Zstd-3, XZ-6, current approved JLZ, candidate JLZ. Columns: Model, Compressed Size with human-readable units, Reduction versus original 211,938,580 bytes, Time to Compress, Time to Decompress. Follow with a three-column percent-change table comparing candidate vs current: Compression Delta, Time to Compress Delta, Time to Decompress Delta. Explicitly show N/A for unavailable historical reference decompress timings, and label Zstd/XZ historical CLI timing as not comparable to JLZ in-memory timing. Use an H1 recommendation marked green for acceptance or red for rejection, then concise summary of change and next priority.
- **Promotion:** improvement in both aggregate size and encoding speed generally acceptable, subject to decoding and format tradeoffs. There is no fixed numerical acceptance threshold. Evaluate size, encoding/decoding, memory, complexity and per-file regressions together; switch to substantial new research directions after repeated diminishing returns. Significant tradeoffs or uncertain measurements are not an automatic acceptance. Report verdict explicitly.

- **Speed-first objective (updated):** User prioritizes approaching or surpassing Zstd-3 practical compression speed, while retaining approximately competitive Zstd-3 compression size. Small archive growth can be worth large compression throughput gains, but only whole-corpus tested candidate changes are promotable. Investigate systematic search-budget reduction, fast matchfinding, and removing redundant transforms. External open-source source code is for inspiration only: preserve JLZ's independently written native codec and provenance. Existing historical Zstd CLI and JLZ in-memory times are not apples-to-apples; don't assert same-host speed ratios.

- **Source organization:** CLI `cmd/jlz`, shared native engine `internal/jlz`, in-package correctness tests beside implementations, byte-exact fixture inputs under `internal/jlz/testdata/fixtures`. Internal algorithms stay in one package until natural acyclic API boundaries are demonstrated. Current module path `github.com/jacoblockett/jlz`; local build `go build -o jlz ./cmd/jlz`. A layout-only refactor must not claim a new compression/speed baseline. See `docs/ARCHITECTURE.md`.
